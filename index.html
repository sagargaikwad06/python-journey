What is the Global Interpreter Lock (GIL) and how do modern production systems bypass it?

The GIL is a mutual exclusion lock used by CPython to prevent multiple native OS threads from executing Python bytecodes simultaneously. It guarantees safe reference counting (Py_INCREF/Py_DECREF) in non-thread-safe memory allocators.

  • Distinction between threads and multiprocessing in Linux (fork copy-on-write).
  • Understanding C-extensions that release GIL explicitly using Py_BEGIN_ALLOW_THREADS.

What is the exact distinction between is and == in CPython?

== assesses value equality by calling the object's __eq__() method. is verifies object identity by checking whether both references point to the exact same physical memory address (id(a) == id(b)).

a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)  # True (Identical elements)
print(a is b)  # False (Distinct memory heaps)

x = 256; y = 256
print(x is y)  # True (-5 to 256 cached singleton table)
Trap to avoid in interviews:

Never use is to compare strings or numbers except for None, True, or False singletons. Python's string interning is an implementation optimization, not a language specification guarantee.
